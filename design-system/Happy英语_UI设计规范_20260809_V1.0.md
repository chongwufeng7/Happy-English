# Happy 英语 UI 设计规范

- 文档版本：V1.0
- 更新日期：2026-08-09
- 适用产品：Happy 英语 Android 应用、HTML 原型、Figma 设计稿
- 基准画板：Android 390 × 844
- 视觉基准：Figma 文件 `7jlwkShHhHp16CKrJ58kiN`，儿童首页节点 `10:3`
- 功能基准：`I:\codex\English star\phase2-lowfi-html`
- 当前状态：基础变量、文字与阴影样式已建立并通过核验，Figma组件库建设中

## 1. 规范目标

本规范用于确保儿童端、家长端、HTML原型和Android应用使用同一套视觉语言。后续页面不得根据单张参考图临时重新定义颜色、字体、圆角、按钮或卡片。

设计关键词：

- 2D扁平插画
- 儿童绘本感
- 明亮活泼
- 温柔治愈
- 简洁高级
- 数据简单且大
- 低认知负担
- 容易阅读、容易点击

## 2. 执行优先级

当不同资料发生冲突时，按以下顺序执行：

1. 当前任务中用户最新的明确要求。
2. 本规范最新版本。
3. 指定的Figma主组件和标准模板。
4. 已确认的标准页面。
5. 产品PRD和产品分解文档。
6. 现有HTML或Android实现。

功能、数据关系和业务文案以产品PRD及现有逻辑为准；视觉值以本规范和Figma组件为准。无法判断时必须先列出冲突，不得自行改变产品含义。

## 3. 强制规则

### 3.1 必须

- 儿童端正文不得小于14px，主要操作文字不得小于16px。
- 可点击区域不得小于48 × 48px；36px状态按钮必须放在不小于48px的可点击容器内。
- 内页存在多个主要操作时，一个按钮占一行。
- 所有页面必须预留Android状态栏、底部安全区域和系统手势区域。
- 图片、角色和插画必须使用正式资源文件；不得使用Emoji、文字字符、占位图或CSS图形冒充。
- Figma正式页面必须使用组件实例；不得复制后脱离主组件。
- 新页面必须复用本规范的颜色变量、文字样式、尺寸变量和效果样式。
- 播放、录音、停止、回放和重录控件必须显示明确状态。
- 颜色不能作为唯一状态表达，必须同时配合文字、图标或形态。

### 3.2 禁止

- 禁止排名、竞赛、倒计时催促和失败惩罚式表达。
- 禁止复杂渐变、强烈霓虹、厚重拟物和高密度数据面板。
- 禁止在一个页面中同时出现多个争夺注意力的主按钮。
- 禁止未经批准改变主角外形、角色标准色和眼睛比例。
- 禁止使用小于12px的用户可见文字。
- 禁止将低保真灰色样式沉淀为正式组件。
- 禁止使用与本规范不一致的第三方通用组件直接替代Happy英语组件。

### 3.3 推荐

- 儿童端每屏突出一个主要任务。
- 主要按钮使用短动词，例如“开始学习”“继续闯关”“播放声音”。
- 错误提示采用鼓励式语言，并提供下一步操作。
- 家长端减少插画面积，但继续使用相同品牌色、圆角和组件体系。

## 4. 品牌与角色

### 4.1 产品名称

- 中文标准写法：`Happy 英语`
- 英文单词首字母大写，Happy与英语之间保留一个空格。
- 儿童姓名示例统一使用`Happy`。

### 4.2 角色

| 角色 | 定位 | 标准特征 | 主要使用场景 |
|---|---|---|---|
| 黑白奶牛猫 | 主角 | 黑白毛色、绿色大眼睛、粉色鼻子、友好挥手 | 欢迎区、关键引导、完成反馈 |
| 紫色变色龙 | 辅助角色 | 紫色身体、圆润轮廓、大眼睛、害羞友好 | 认读、探索、提示 |
| 鹦鹉 | 辅助角色 | 红橙主体、黄色翅膀和喙、蓝色尾羽 | 听力、跟读、声音反馈 |
| 星星 | 激励角色 | 暖黄色、圆润五角、友好表情 | 星星数量、奖励、完成反馈 |

角色必须保持圆润、无攻击性、表情清晰。角色素材优先使用透明背景PNG或WebP；标准图标使用SVG。合成场景不得假装拆分为可编辑矢量角色。

## 6. 字体与文字

### 6.1 字体家族

- 中文与英文首选：`Noto Sans SC`
- Android回退：系统无衬线中文字体
- Web回退：`Microsoft YaHei, sans-serif`
- 数字与导航不得为了视觉效果使用难以稳定加载的特殊字体。

### 6.2 文字样式

| Figma文字样式 | 字号/行高 | 字重 | 使用场景 |
|---|---|---|---|
| `Display/Data` | 36/36 | Bold | 进度、星星等核心数据 |
| `Heading/Page` | 24/30 | Black | 页面欢迎语、一级标题 |
| `Heading/Section` | 21/28 | Bold | 模块标题 |
| `Heading/Card` | 19/24 | Bold | 任务、卡片标题 |
| `Body/Large` | 17/24 | Black | 欢迎文案、重要说明 |
| `Body/Medium` | 16/24 | Bold | 普通正文 |
| `Body/Small` | 14/20 | Bold | 任务说明 |
| `Label/Large` | 16/20 | Bold | 大按钮、标签 |
| `Label/Medium` | 14/20 | Bold | 状态按钮、导航文字 |

同一页面最多使用四个字号层级。儿童端不使用细字重；辅助文字仍需保持足够对比度。

### 7.2 布局规则

- 390px画板的页面左右边距统一为14px。
- 主要内容宽度为362px左右。
- 首页数据卡使用两列布局，列间距12px。
- 首页任务行高度68px；其他内页任务卡根据内容自适应，但不得小于68px。
- 底部导航高度70px，必须额外处理系统手势安全区域。
- 页面最后一个可滚动内容与固定底部导航之间至少保留92px。
- 主要按钮高度50px；录音等关键操作建议56px。

## 9. 图标规范

- 风格：扁平、圆润、俏皮、双色层次、统一视觉重量。
- 正式图标必须为SVG或Figma原生矢量。
- 底部导航图标基准为30 × 30px。
- 图标不可使用Emoji、Unicode字符或CSS绘制。
- 同组图标必须使用相同边界框、视觉中心和颜色饱和度。
- 图标内部装饰色可以固定，但外部语义颜色必须绑定设计变量。

儿童端底部导航固定三个一级入口：

1. 首页：绿色。
2. 闯关：紫色。
3. 奖励：橙色。

## 10. 组件规范

### 10.1 状态要求

每个可交互组件按适用范围定义：

- Default
- Pressed
- Selected
- Completed
- Disabled
- Loading
- Error
- Empty
- Permission denied

### 10.2 按钮

- Primary：黄色底、深棕文字、白色高光边框、暖黄色底部投影。
- Secondary：白色或浅色表面、深棕文字、清晰描边。
- Text：无容器或轻量容器，用于返回、取消和辅助操作。
- 同一内容区域不得并排放置两个同等权重的主要按钮。
- 内页按钮默认全宽、一个按钮一行。

### 10.3 卡片

- Surface Card：白色94%–100%表面、暖灰边框、轻阴影。
- Metric Card：图标在左、标题和大数据在右；高度90px。
- Task Row：角色图标、任务文字、状态按钮三段结构。
- 卡片中不展示与当前任务无关的复杂信息。

### 10.4 导航

- 一级页面显示底部导航。
- 二级页面不显示一级导航，顶部提供明确返回按钮。
- 页面名称位于顶部左侧或视觉中心，必须遵循对应模板。
- 星星总数只在规定的一级页面展示；星星账单内页使用返回导航。

### 10.5 学习硬件控件

- 播放、录音、停止、回放、重录分别使用独立、明确的图标和文字。
- 录音中必须显示持续状态，不得让儿童猜测设备是否工作。
- 麦克风权限被拒绝时提供“去设置”和“暂不录音”路径。
- 扬声器、有线耳机和蓝牙耳机切换不得改变主要操作位置。
- 录音完成后必须支持播放自己的录音和重新录音。

## 11. 页面模板

### 11.1 儿童端一级页面

结构：系统状态栏 → 一级顶部区 → 页面内容 → 固定底部导航。

### 11.2 儿童端学习内页

结构：系统状态栏 → 返回导航 → 内容说明 → 主要互动区 → 单列操作按钮。不得展示底部一级导航。

### 11.3 家长端一级页面

使用相同品牌基础色和圆角，减少大面积插画，强调清晰信息、表单和报告。

### 11.4 家长端内页

结构：系统状态栏 → 页面名称/返回 → 内容卡片 → 单列操作。切换儿童端弹窗始终位于屏幕中心。

## 12. Android适配

- 设计基准为390 × 844，但必须支持宽度320px及以上。
- 状态栏图标颜色根据背景自动选择深色模式；当前主方案使用深色状态栏图标。
- 所有固定底部组件必须加入系统手势安全区。
- 字体缩放后不得遮挡按钮或隐藏主要内容。
- 关键控件使用Android无障碍语义标签。
- 横屏不是V1.0主要设计目标，但不得导致应用崩溃或主要操作不可达。

## 13. Figma执行规则

- 变量先于组件创建。
- 语义颜色必须引用Primitives，不得复制原始颜色值。
- 正式页面只使用组件实例和变量绑定。
- 组件使用Auto Layout。
- 组件变体命名格式：`Property=Value, Property=Value`。
- 图标通过Instance Swap属性替换，不为每个图标创建一套按钮变体。
- 每个组件必须填写用途、使用规则和禁止用法。
- 每个组件必须通过结构检查和截图检查。

## 16. 验收清单

新页面提交前必须检查：

- 是否使用390 × 844基准并包含Android状态栏。
- 是否全部使用正式变量和组件。
- 是否存在小于48px的主要点击区域。
- 是否有小于14px的儿童端正文。
- 是否出现Emoji、占位图或临时图标。
- 是否修改了未经授权的数据、文案或业务逻辑。
- 是否提供默认、按下、完成、禁用和错误等必要状态。
- 是否检查底部导航和系统手势区域遮挡。
- 是否在同尺寸下与Figma模板进行截图对照。

## 17. 版本管理

命名格式：

`Happy英语_UI设计规范_YYYYMMDD_V主版本.次版本.md`

同一天更新时递增次版本；跨日期更新时使用新日期并从V1.0开始。任何颜色、字体、组件结构或角色规则变更都必须记录原因和影响页面。
